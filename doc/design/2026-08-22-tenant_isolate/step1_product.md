# 多租户隔离（Tenant）- 产品文档

> 状态：规划中（尚未实施）

## 目标

当前网关是**全局单租户**：`user` / `model` / `vendor` / `vendor_model` 等实体之间没有任何隔离维度。模型名（`model.name`）对启用模型全局唯一，供应商（`vendor`）全局共享，用户（`user`）全局平铺。

这带来两个问题：

1. **命名冲突**：两个团队都想建一个叫 `gpt-4o` 的对外模型、或各自配置一个 `openai` 供应商时，会互相冲突或串数据。
2. **数据混杂**：A 团队能看到 B 团队的模型 / 供应商 / 用户 / 请求记录，无法按组织边界管理。

引入**租户（tenant）**概念，让 `user` / `model` / `vendor` 按租户区分，实现多租户隔离。

## 功能特性

### 功能开关

- 多租户隔离作为**功能开关**，可开启 / 关闭。
- **默认状态**：存量部署迁移后默认关闭，行为与迁移前一致；需要多租户时显式开启。
- **关闭时**：系统进入**逻辑单租户模式**。所有租户业务请求固定按 `main` 过滤；非 `main` 租户及其数据保留在数据库中，但不通过任何业务 API 暴露。重新开启后，原有非 `main` 数据恢复可访问。
- **开启时**：启用完整的多租户隔离语义（租户归属、租户内唯一、跨租户过滤），所有请求必须按租户过滤。

### 租户归属模型

- 用户、模型、供应商、请求规则按租户归属，同名字段在租户内唯一、租户间可共存。
- 引入 `tenant` 数据表作为隔离维度的根实体。
- 租户可删除：仅「空租户」（无用户 / 模型 / 供应商）可删，`main` 租户不可删；删除时忽略其历史请求 / 充值记录（这些记录随之成为不可达死数据，仅占存储，可接受）。

### 请求的租户区分

多租户功能**开启**时，每个请求按以下规则解析到单一租户：

1. 每个请求最终都对应到**单一租户**。
2. 请求显式指定租户（请求头 `X-Tenant-ID`）时，使用请求指定的租户。
3. 请求未显式指定时，使用用户所属的租户。

> 补充约束：普通用户（admin / normal）不能越权——其显式指定的租户必须与自身租户一致，否则拒绝（403）；root 无归属租户，未显式指定时缺省为 `main`。

多租户功能**关闭**时，不区分租户，所有请求一律对应到 `main` 租户（见「功能开关」）。

### 模型跨租户共享

- 模型支持「租户私有 + 全局共享」两种形态。
- 私有模型仅本租户可用；共享模型对所有租户可用。
- **仅 `main` 租户下的模型可配置为全局共享**，其它租户的模型只能私有。
- 启用模型名称仅在**所属租户内唯一**。调用方租户存在同名私有模型时，优先使用私有模型；否则回退到 `main` 租户的共享模型。
- **管理端模型列表可见共享模型**：非 `main` 租户（admin，或 root 处于非 `main` 视角）查看模型列表时，除本租户模型外，还额外显示 `main` 租户下的共享模型（`cross_tenant = 1`），且为**只读**（不可编辑 / 删除）；`main` 租户自身查看时即其全部模型，无变化。
- 共享模型若处于禁用状态（`enable = 0`），在其它租户列表**仍显示、但标注为禁用且不可调用**（管理列表不过滤启用状态，LLM 调用按启用过滤）。
- 共享模型的计费：调用方租户余额照常扣减；上游真实费用由 `main` 租户（共享模型所属）承担，v1 不做跨租户结算；共享模型调用在 `main` 侧**不计入成本统计**（v1 简化，`main` 承担上游账单但统计口径不含跨租户共享调用）。

### 请求规则租户化

- 请求规则（RPM 限流 / 访问控制）按租户归属，支持「租户私有 + 全局共享」两种形态，与模型共享语义一致。
- **私有规则**仅对本租户请求生效、仅本租户 admin 可见 / 编辑。
- **全局共享规则**对所有租户请求生效；**仅 `main` 租户可配置共享规则**，其它租户可见但**只读**（不可编辑 / 删除 / 启用）。
- 共享规则是全网关级策略，限流计数按规则全局统计（跨租户共享同一预算）；租户私有规则的限流计数天然只统计本租户请求。
- 规则 scope 引用的供应商须与规则同租户（共享规则引用 `main` 供应商）；引用的模型 / 用户限定在「本租户资源 ∪ main 共享模型」范围内。
- 功能开关关闭时，规则一律按 `main` 租户解析，行为与迁移前一致。

### 软隔离与权限层级

- 管理端默认按租户过滤，root 可跨租户查看 / 管理。
- `ROOT` 可管理租户本身，开启时须显式指定视角租户；`ADMIN` / `NORMAL` 归属某租户，只在本租户内操作。
- 请求记录按请求视角租户归属：root 在哪个租户视角下发起调用，记录就记到哪个租户（不随模型归属）；普通用户记到自身租户。该归属决定请求记录列表与统计的可见范围。

### 存量数据无感迁移

- 单租户 → 多租户无缝迁移，存量数据自动归入 `main` 租户，既有行为不变。

### 前端呈现

- 新增「租户管理」页（root 专用）：租户列表 / 创建 / 编辑 / 删除（`main` 租户不可删）。
- root 在顶部导航可**切换租户视角**，各列表（用户 / 供应商 / 模型 / 请求记录 / 充值记录）按所选视角过滤；admin 无此入口，默认只看本租户。
- 模型表单新增「跨租户共享」开关，仅 `main` 租户下的模型可勾选。
- 模型列表：非 `main` 租户视角下额外显示 `main` 租户的共享模型，标注「共享」并置只读（编辑 / 删除 / 启用开关均禁用）；禁用的共享模型标注「已禁用」。
- 规则管理页租户化：列表并入 `main` 租户的共享规则（标注「共享」、只读）；规则表单新增「全局共享」开关，仅 `main` 租户视角可勾选。
- 侧边栏 config（设置）与 client-config（客户端配置）入口仅在 `main` 租户视角下显示；非 `main` 视角隐藏。
- 功能开关关闭时，隐藏「租户管理」与视角切换入口，退回单租户界面。

## 产品边界（非目标）

- 不做硬性行级安全策略（RLS）——本版本是「软隔离 / 归属标签」语义，跨租户隔离靠查询过滤 + 写路径归属校验保证。
- 不改动协议转换、计费、路由策略等既有业务行为。
- 不引入租户级配额 / 独立计费账户（后续版本可扩展）。
- 供应商不做跨租户共享（仅模型支持共享）。
- client-config 中的 `model` 按 `main` 租户模型解析（v1 简化，暂不支持按调用方租户解析）；client-config 仅 `main` 租户视角可用，`(client, name)` 全局唯一（若后续放开非 `main` 租户 client-config 需重审该唯一约束）。
- 请求记录清空（clear-all / clear-payload）按租户隔离，不再是全局清空。

## 验收标准

- [ ] 同名模型跨租户共存，各自解析到各自上游，互不串扰。
- [ ] 共享规则对所有租户生效、私有规则仅本租户生效；非 `main` 租户可见共享规则但不可编辑；仅 `main` 租户规则可标记为全局共享。
- [ ] 普通 admin 看不到、也写不进其它租户的数据。
- [ ] root 可管理租户本身，并可跨租户查看 / 操作。
- [ ] 共享模型对所有租户可用；私有模型仅本租户可用。
- [ ] 仅 `main` 租户下的模型可配置为全局共享。
- [ ] 非 `main` 租户查看模型列表时能看到 `main` 租户的共享模型（只读），不能编辑 / 删除。
- [ ] 关闭多租户隔离后，仅逻辑暴露 `main` 租户；非 `main` 数据保留且不可访问，重新开启后可恢复。
- [ ] 存量数据迁移后归入 `main` 租户，既有行为不变。
- [ ] `user.token` 仍全局唯一；`vendor.name` 与启用的 `model.name` 均在租户内唯一；同名私有模型优先于共享模型解析。
