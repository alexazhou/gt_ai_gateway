# 测试请求支持多模态（图片）输入 - 产品文档

> 状态：规划中（尚未实现）。日期为设计稿创建日期，落地后按发布 tag 日期归档。
>
> **状态更新（2026-10-21）**：OpenAI ↔ Anthropic 图片转换已在协议转换修复中补齐（含工具结果图片）。本文中"当前转换器不支持图片"的前提、结果区丢图警告和"跨协议限制"边界已失效；实现本功能时无需再区分转换方向。

## 目标

网关的「供应商连通性测试」和「模型可用性测试」目前只能发送纯文本 `ping` / `你好`，无法验证上游模型是否支持图片输入。用户要测视觉模型时，只能自己用 curl / SDK 另行构造请求。

本需求在测试对话框中加入**请求类型切换**：文本 / 多模态（图片）。选择多模态后，网关发送「一张内置测试图片 + 一句文本提示」，用现有测试链路验证模型能否正常接收并理解图片输入。

## 功能特性

### 请求类型切换

- 测试对话框新增「请求类型」单选：**文本**（默认）/ **多模态（图片）**
- 切换请求类型时清空上一次测试结果，避免结果与当前选择不一致
- 文本模式保持现有行为不变（请求体、提示词、token 上限均不改）

### 内置测试图片

- 图片由后端内置（base64 常量），不依赖外部图床，离线 / 内网环境也可用
- 固定为一张小尺寸 PNG（建议 64×64、纯色背景 + 简单几何图形），体积控制在 4KB 以内
- 多模态模式默认提示词：`请描述这张图片`
- 不提供本地上传、图片 URL、音频 / 文件等输入方式（见产品边界）

### 覆盖两个测试入口

| 入口 | 接口 | 行为 |
|------|------|------|
| 供应商连通性测试 | `POST /vendor/:id/test.json` | 按所选协议直接向上游发送多模态请求体；`auto_convert` 打开时按最终上游协议原生构造 |
| 模型可用性测试 | `POST /model/route-test.json` | 以所选客户端协议构造多模态请求，走真实网关路由与协议转换 |

### 结果展示

- 请求详情 Tab 直接展示实际发送的请求体（含图片 base64），与现有文本测试一致
- 模型可用性测试的路由结果经过协议转换时，图片按当前转换器能力转发；六向图片转换均已支持，不再需要丢图警告
- 成功判定维持现状：上游 HTTP 2xx 即为连接成功，不校验模型回答内容

## 产品边界

- **仅图片 + 文本**：不包含音频、视频、文件输入
- **仅内置样图**：不开放本地上传与图片 URL，避免文件大小、格式校验与 SSRF 等额外问题
- **跨协议能力**：OpenAI / Anthropic / Responses 六向图片转换均已支持，模型路由测试不再需要区分转换方向
- 不改变测试请求的计费、记录、活动时间线等既有链路

## 验收标准

- [ ] 两个测试对话框都能在「文本」与「多模态（图片）」之间切换，切换后结果清空
- [ ] 文本模式的请求体与当前实现完全一致（回归用例通过）
- [ ] 多模态模式在 OpenAI / Anthropic / Responses 三种协议及跨协议路由场景下，上游能收到符合协议规范的图片内容
- [ ] 多模态模式的提示词与 token 上限足够让模型返回可读内容（不再是 `max_tokens: 1`）
- [ ] 模型路由测试在跨协议路由时，图片仍能正确转发
- [ ] 请求详情 Tab 能看到实际发送的图片内容
