# 直接用「渠道/模型ID」调用（临时模型，不写数据库）- 产品文档

> 对应 issue：<https://github.com/alexazhou/gt_ai_gateway/issues/24>

## 目标

现在必须先「添加模型」才能调用：请求里的 `model` 必须在模型表里存在且已启用，否则直接报错（不存在 → `model not found`，已停用 → `model disabled`）。对只想快速试一下某个渠道下某个模型的用户，这一步是多余的。

本迭代支持**直连调用**：配好渠道 A 之后，直接用 `A/gpt-4o-mini` 这样的模型名就能调用，不需要先建模型。这种调用**不带负载均衡、不带故障切换**（就打到 A 这一个渠道）；需要负载均衡 / 故障切换时，再手动建模型来配置。

**明确的边界：直连调用不往模型表、也不往渠道的模型列表（vendor_model）里写任何东西。** 调用结束后不留痕迹，模型列表和渠道的模型下拉都不会因此多出记录；但请求照常写入记录（网关的核心能力是全量记录，直连调用不能被排除在外）。

## 功能特性

### 调用语法

```
<渠道名>/<模型ID>
```

- **按第一个 `/` 切分**：前半是渠道名，后半整体是模型 ID。模型 ID 里可以继续带 `/`——`A/Qwen/Qwen2.5-7B` 解析为渠道 `A` + 模型 `Qwen/Qwen2.5-7B`（OpenRouter、HF 这类模型 ID 很常见）。
- 前提是**渠道名里不能出现 `/`**：创建 / 改名渠道时校验拒绝，并写进使用文档。
- 三个 LLM 端点（`/llm/v1/chat/completions`、`/llm/v1/messages`、`/llm/v1/responses`）都支持，含自动协议转换（例如 OpenAI 客户端 + 只配了 Responses 的渠道 → 转 Responses）。

### 查找顺序（向后兼容）

1. **先按完整模型名精确匹配**：命中已启用的模型 → 用它。
2. 没找到启用的模型、但模型存在（已停用）→ 报 `model disabled`（403）。
3. 模型完全不存在：
   - 名字不含 `/` → 维持现状的 `model not found`；
   - 名字含 `/` → 按 `渠道/模型ID` 解析：
     - 渠道按**调用方租户**查，查不到 → 报 `model not found`；
     - **解析出的模型 ID 如果有一个已启用的同名模型**（调用方可见范围）→ 直接用那个模型：价格、负载均衡、规则全部生效。「想给直连调用配价格 / 加多上游」的动作就是建一个同名模型，不需要改调用方；
     - **同名模型存在但已停用** → 报 `model disabled`（403），不走直连；
     - **同名模型完全不存在** → 走临时模型（见下）。

**错误口径**：渠道不存在、模型不存在统一报 `model not found`（避免把渠道列表泄露给客户端，具体原因只写服务端日志）；**模型存在但已停用则报 `model disabled`（403）**，让客户端能区分「没有这个模型」和「模型被停用」。停用判断对所有入口统一生效；只有「不存在时是否尝试直连」受直连开关控制。

### 临时模型（只存在于本次请求内存里）

直连调用在请求期间构造一份**临时的、存在于内存里的模型配置**：

- 上游收到的 `model` 是**去掉渠道前缀的模型 ID**（`A/gpt-4o-mini` → 上游收到 `gpt-4o-mini`）；
- 没有价格 → 该次调用 **cost = 0**（usage 照常记录）；要计费就建同名模型并配价格；

### 记录与展示

- 直连调用照常写入记录：`model_id` 为空（不属于任何已登记模型），并新增**模型名快照** `model_name`，存客户端请求里的模型名原文（直连是 `A/gpt-4o-mini`，普通调用就是当时的模型名），**所有记录都写**。
- 快照的意义：模型是可编辑、可删除的——只存 id 的话，改个名，一年前的记录也跟着改名；删掉模型，旧记录就查不出叫什么了。快照让每条记录冻结「当时调用方写的是什么」，模型改名 / 删除后历史记录仍显示**当时的**名字。
- 记录列表 / 详情 / 仪表盘「最近记录」：模型列优先显示 `model_name` 快照；`model_id` 也为空（直连调用）时标注**「未登记模型」**。
- 统计仍按 `model_id` 聚合（id 稳定，改名不影响归组），直连调用不单独归组。
- 按模型筛选（`model_ids`）自然只匹配已登记的记录。

### 配置开关（默认关闭）

直连调用由**全局配置开关**控制（设置页，与「计费模块」「API playground」等模块开关同一入口；不按租户区分）。需要按租户控制时，走「关闭开关 + 各租户自建模型」的方式：

- **默认关闭**：升级后除「停用模型改为报 `model disabled`」这一处统一修正外，其余行为不变，需要时再去设置页打开。原因：直连会绕过模型级规则、也不计费（cost = 0），等于租户里任何用户都能免费用任意渠道的任意模型。这是放宽管控，应该由管理员主动开启；
- **关闭时**：`渠道/模型ID` 形式、且模型完全不存在时，仍报 `model not found`（与迭代前一致）；名字带 `/` 的存量模型照常先走精确匹配。

### 渠道名校验

创建 / 更新渠道时拒绝含 `/` 的名字（会破坏直连语法）。存量数据不迁移、不改名；含 `/` 的存量渠道将无法用于直连调用（见产品边界）。

## 产品边界（非目标）

- **不做负载均衡、不做故障切换**：直连固定只走一个渠道、失败也不切换（`SINGLE` + 关闭 failover）。需要 LB / 切换就建一个**同名模型**——但一旦存在同名多上游模型，`A/gpt-4o-mini` 会走那个模型（可能分配到 B/C 渠道），客户端指定渠道 A 的意图会被忽略。想固定渠道，就把该模型只配 A 一个上游。
- **不做「第一次调用时自动创建模型」**：自动往模型表插一条，会让拼错的名字、临时试用的名字都留下记录，还得人工清理。既然 issue 明确不要这个行为，模型表就保持干净。
- **`/llm/v1/models` 不列出直连模型**：模型列表仍只展示已登记的模型，客户端的模型自动发现看不到直连模型（按渠道名 + 模型 ID 手写）。
- **渠道改名 / 删除后直连调用随之失效**（渠道名是调用语法的一部分），报 `model not found`。
- **要禁止某个渠道模型，停用同名模型即可**：停用后直连同样报 `model disabled`，不会被绕过。
- **老数据里已经带 `/` 的渠道名，不能用于直连**：这类渠道不迁移、不改名，但它无法通过 `A/B/<模型ID>` 调用（会被解析成渠道 `A` + 模型 `B/<模型ID>`）。需要直连时请先给渠道改名。
- **直连调用不参与模型级规则**（无 id 可匹配），但用户级规则照常生效；也不做按 `model_name` 原文的规则匹配（本期规则维度只有 id）。
- **不影响现有调用方式**：按模型名调用时，路由、协议转换、计费都和现在完全一样。直连只是在内部改用临时模型，并允许记录里的 `model_id` 为空。

## 验收标准

- [ ] **开关默认关闭**：未开启开关时，模型完全不存在（`A/gpt-4o-mini`）→ `model not found`，与迭代前一致；现有启用模型的调用不受影响；设置页可开启 / 关闭，即时生效
- [ ] 调用一个已停用、名字不带 `/` 的普通模型 → 403 `model disabled`，与直连开关状态无关
- [ ] 配好渠道 A（配了 openai URL）后，**开启开关**，用 `A/gpt-4o-mini` 调 `/llm/v1/chat/completions` → 200，正常返回
- [ ] 该请求的记录：`model_id` 为空，`model_name` 快照为 `A/gpt-4o-mini`，`vendor_id` 指向渠道 A、`vendor_model_name` 为 `gpt-4o-mini`，`cost = 0`、usage 有值
- [ ] **模型列表里不会多出任何模型**（直连调用不写模型表）
- [ ] **渠道的模型列表（vendor_model）也不会多出记录**：直连调用前后该渠道的模型数量不变
- [ ] 因模型停用、规则拒绝、余额不足或上游失败而结束的请求，记录里的 `model_name` 快照同样是客户端原文 `A/gpt-4o-mini`，不是去掉渠道前缀后的 `gpt-4o-mini`
- [ ] 记录列表 / 详情 / 仪表盘「最近记录」里能看出「渠道 A + gpt-4o-mini」，并标注「未登记模型」
- [ ] 模型 ID 含 `/`（`A/Qwen/Qwen2.5-7B`）→ 解析正确，上游收到的 model 是 `Qwen/Qwen2.5-7B`
- [ ] 渠道名不存在（`NoSuchVendor/xxx`）→ 报 `model not found`，日志里有具体原因，响应里不区分
- [ ] 三个端点都可用（含需要协议转换的组合，如 OpenAI 客户端 + 只配 Responses 的渠道）
- [ ] 手动建一个名为 `gpt-4o-mini` 的模型（绑渠道 A、带价格、开负载均衡）后，再调 `A/gpt-4o-mini` → 走这个模型（计费 > 0、请求在多个上游间分配、按模型配的规则生效）
- [ ] 把该同名模型**停用**后再调 `A/gpt-4o-mini` → 报 `model disabled`（403），不会走直连
- [ ] 把该同名模型**删除**后再调 `A/gpt-4o-mini` → 走临时模型直连渠道 A（不计费、不参与负载均衡）
- [ ] 把一个模型改名（或删除）后，它此前产生的记录仍显示**当时的**名字（快照生效），统计里的归组不变
- [ ] 按模型维度（含 `!=` / `not in` 反向条件）配置的规则对直连调用不生效；按用户维度的规则照常生效
- [ ] 创建 / 更新含 `/` 的渠道名（`A/B`）→ 报错拒绝；已有渠道数据不会被修改
- [ ] 后端测试（node 模式）、TypeScript 静态类型检查、前端构建均通过
