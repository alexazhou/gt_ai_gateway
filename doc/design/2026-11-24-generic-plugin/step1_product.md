# 请求插件规则化 - 产品文档

## 目标

网关目前内置了三个请求改写功能（强制改写 CCH、屏蔽 Claude Code 跟踪、Responses API 粘性路由），但只能通过「高级设置 → 请求处理」全局一刀切地启停，无法按用户、模型或供应商精细控制。

本迭代将请求改写统一纳入**规则体系**，并为所有规则引入**优先级**：
- **保留快捷开关，联动系统规则**：「高级设置 → 请求处理」下的三个开关继续保留，启停时自动同步对应的**系统规则**。
- **支持自定义用户规则**：管理员可在「规则管理」创建「请求插件」类型的**用户规则**，按用户 / 模型 / 供应商条件触发插件并自定义参数。
- **规则优先级控制顺序**：规则统一具备优先级，插件本身不设优先级，完全跟随触发它的规则顺序执行。

## 功能特性

### 1. 系统规则与用户规则

| 类别 | 来源 | 优先级 | 规则管理页操作 | 说明 |
|---|---|---|---|---|
| **系统规则** | 「高级设置 → 请求处理」自动生成与联动 | 系统固定（`10 / 20 / 30`） | **完全只读** | 承载全局默认请求处理开关，启停统一在「高级设置」中操作 |
| **用户规则** | 管理员在「规则管理」手动创建 | 可配置（`0 ~ 10000`，默认 `100`） | 新建、编辑、启停、删除 | 按用户、模型、供应商组合条件定制限流、访问控制或请求插件 |

- 「规则管理」页面分**「用户规则」**和**「系统规则」**两区展示，均按执行顺序（优先级从小到大，同优先级按 ID 从小到大）排列。
- 系统规则区只读展示状态与优先级，并提示前往「高级设置 → 请求处理」修改（非主租户视图提示由系统管理员在主租户统一配置）。

### 2. 高级设置「请求处理」联动

| 设置项 | 系统规则预置优先级 | 内置插件作用 | 用户规则可配参数 |
|---|---|---|---|
| **屏蔽 Claude Code 跟踪** | `10` | 规范化系统提示词中的日期追踪标记，避免破坏缓存命中 | 无 |
| **强制改写 CCH** | `20` | 将 Anthropic 系统提示词开头的 `cch=xxx;` 改写为指定值 | `cchValue`（默认 `A1234`） |
| **Responses API 粘性路由** | `30` | 请求未携带 `prompt_cache_key` 时自动注入，提升缓存命中率 | 无 |

- 保存后当前实例立即生效，多实例部署下其他实例最迟 60 秒内生效。
- 一并修复旧版「屏蔽 Claude Code 跟踪」前后端字段名不一致导致关闭不生效的问题，升级后以界面最后保存的状态为准。

### 3. 规则优先级与「请求插件」规则

- **优先级（所有规则通用）**：整数 `0 ~ 10000`，默认 `100`，**数值越小越先执行**（同优先级按规则 ID 从小到大执行）。
- **请求插件规则配置**：
  - 匹配条件复用现有条件树（全局，或用户 / 模型 / 供应商组合）；
  - 下拉选择内置插件，插件参数以 **JSON 文本**填写（选填，留空视为 `{}`），保存时由后端校验格式与参数合法性。
- **多规则管道执行（不去重）**：
  - 同一请求命中多条插件规则（含系统规则与用户规则同时命中）时，按优先级顺序**全部依次执行**，后执行的规则在前序结果上继续改写。
  - 例如「强制改写 CCH」：系统规则（`20`）先改为 `A1234`，默认优先级的用户规则（`100`）后改为 `B5678`，最终生效为 `B5678`；若某插件属于“为空时注入”且希望先于系统规则生效，可将用户规则优先级设为 `< 30`。
- **其他规则类型**：访问控制与频率限制维持原有的「路由前/路由后分流」及「访问控制先于频率限制」不变，同阶段同类型内按优先级顺序检查（限流仍保持命中规则全部生效）。

### 4. 执行与容错体验

- **跨协议适配**：同协议直通或跨协议转换场景下，插件均在对应协议阶段自动生效。
- **失败切换重匹配**：触发上游 failover 切换供应商时，按新供应商重新匹配插件规则。
- **异常不阻断**：插件执行异常或补丁越界时仅在请求时间线记录告警，请求照常转发。
- **时间线留痕**：仅当插件实际修改了请求时，在请求详情时间线记录生效的插件、规则、优先级与修改路径（不记录内容原文）。

## 产品边界（非目标）

- 不支持用户上传自定义插件脚本（插件由系统内置提供）。
- 插件自身不设独立优先级，完全跟随规则优先级。
- 不改写上游响应内容，不按请求体内容做规则条件匹配。
- 插件参数不提供字段化表单，仅提供 JSON 文本输入与后端校验。

## 验收标准

- [ ] 升级后生成三条预置系统规则（优先级 `10 / 20 / 30`），启用状态与高级设置开关一致；存量规则优先级回填为 `100`
- [ ] 「高级设置 → 请求处理」切换开关时同步更新对应系统规则状态；「屏蔽 Claude Code 跟踪」关闭后真实生效
- [ ] 系统规则在页面与接口层完全只读（任何修改或删除均返回 `403`）
- [ ] 规则管理分「用户规则 / 系统规则」两区并按优先级顺序展示；支持创建、编辑、启停、删除「请求插件」用户规则
- [ ] 优先级（`0 ~ 10000` 整数）与插件 JSON 参数校验生效，非法输入拒绝保存并提示原因
- [ ] 多条插件规则同时命中时按「优先级升序 → ID 升序」依次叠加生效
- [ ] 同协议直通、跨协议转换、上游 failover 场景下插件均正确生效
- [ ] 实际发生改写时时间线可见插件记录，未改写不留空记录，历史记录正常展示
