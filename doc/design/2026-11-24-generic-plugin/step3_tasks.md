# 请求插件规则化 - 实施任务拆分

## 依赖关系

```text
T1 插件框架 ──┬─→ T2 内置插件迁移 ──┐
              │                      ├─→ T5 sender 管线集成 ──┐
T3 规则模型与接口 ─┬─→ T4 设置联动 ─┘                        ├─→ T7 集成测试与回归
                   └─→ T6 前端与 CLI ─────────────────────────┘
```

## 任务清单

| # | 任务 | 主要内容 | 验收标准 | 依赖 |
|---|---|---|---|---|
| T1 | 插件框架 | 定义插件与补丁类型、`pluginRegistry` 注册中心、JSON/Header Patch 应用与保护边界拦截 | 补丁增删改、保护字段/保护头拦截、原子拒绝单测通过 | — |
| T2 | 内置插件迁移 | 将三个现有插件改造为新接口，补充 `cchRewriter` 参数校验与示例配置 | 三个插件原有单测用例行为等价通过，新增参数校验单测通过 | T1 |
| T3 | 规则模型与接口 | `migrate_0035`（加列、合并旧 tracking 配置键、预置三条系统规则）；规则 `priority` / `source` / `pluginConfig` 校验与系统规则 `403` 只读保护；`/rule/plugins.json` 与 `list.json?source=` 接口 | 迁移测试、系统规则只读保护、优先级与参数校验、列表排序与筛选测试通过 | — |
| T4 | 高级设置联动 | `configService` 修改三个请求处理开关时同步更新对应 `biz_id` 系统规则并失效缓存；兼容旧 tracking 键名提交 | 切换高级设置开关后系统规则状态即时同步生效 | T3 |
| T5 | sender 管线集成 | `senderService` 接入转换前/转换后插件调度，写入新版 `plugin` 阶段时间线与告警记录 | 同协议、跨协议、failover 重匹配、插件异常容错测试通过 | T1、T2、T3 |
| T6 | 前端与 CLI | 规则页分「用户规则 / 系统规则」两区并展示优先级；弹窗支持优先级与插件 JSON 配置；修正高级设置 tracking 字段；时间线兼容新旧格式；CLI 同步 `gtgw rule plugins` 与 `route-map.json` | 前端构建通过，CLI `go test ./...` 通过，页面交互走查正常 | T3 |
| T7 | 集成测试与回归 | 端到端覆盖多规则优先级叠加、作用域匹配、跨协议与 failover；适配测试清表时的默认系统规则初始化 | 后端测试、TS 类型检查、前端构建、CLI 测试全绿 | T2、T4、T5、T6 |
