# main 租户 admin 与 root 管理权限对齐 — 产品文档

## 背景

多租户隔离（[2026-08-22-tenant_isolate](../2026-08-22-tenant_isolate/step1_product.md)）落地后，管理端权限出现两类角色：

- **root**：由 `ROOT_TOKEN` 提供、无归属租户，可管理租户本身、跨租户查看 / 管理。
- **admin**：归属某租户，只在本租户内操作。

其中「租户管理」「跨租户视角切换」「多租户隔离开关」按原设计仅对 root 开放。这带来一个现实问题：**单租户部署（多租户开关默认关闭）下，系统只有一个 main 租户，root 之外的 admin 实际上是本系统的实际管理者，但无法使用上述能力**；同时前后端对「多租户开关」的校验也不一致（前端禁用、后端未校验）。

本专项把这组差异收敛为明确的角色定义：引入**系统管理员**，让**归属 main 租户的 admin 与 root 管理权限完全等价**。

## 核心概念：系统管理员

> **系统管理员 = `root` 用户，或归属 `main` 租户的 `admin` 用户。**（`normal` 用户永不是）
>
> 系统管理员只覆盖**管理权限**。`root` 的**身份性**能力（`ROOT_USER_ID = -1`、无限余额、不计费）**不**随之下放。
>
> **LLM 调用权限不在本次对齐范围内，且方向相反**：限流与访问控制规则对所有用户一视同仁，**root 也不再旁路**（见 [2026-08-22-advanced_access_control](../2026-08-22-advanced_access_control/step1_product.md)）。

判定基准是用户的**归属租户**（`user.tenant_id === main 租户 id`），与多租户隔离功能开关的状态**无关**。含义：

- 隔离关闭时，所有请求虽都落在 main，但归属其它租户的 admin **不会**因此获得系统管理员权限；
- root 无归属租户，恒为系统管理员。

## 功能特性

在 main 租户下，系统管理员（root 或 main 租户 admin）拥有完全一致的管理能力：

| 能力 | 说明 |
|------|------|
| 租户管理 | 租户列表 / 创建 / 编辑 / 删除（`main` 租户不可删，非空租户不可删） |
| 跨租户视角 | 可通过 `X-Tenant-ID` 指定任意存在的租户，读写该租户的用户 / 供应商 / 模型 / 规则 / 请求记录 / 充值记录 |
| 多租户隔离开关 | 可修改 `multi_tenant_enabled` |

非系统管理员（其它租户的 admin、全部 normal 用户）行为不变：

- 租户管理端点一律 `403`；
- `X-Tenant-ID` 必须等于自身租户，否则 `403`；
- 无法修改 `multi_tenant_enabled`（改值即 `403`，携带原值提交不拒绝）。

**调用 LLM 的规则约束对所有用户一视同仁**：main 租户 admin、其它租户 admin、normal 用户、root 都照常受限流与访问控制规则约束 —— 管理权限的下放与调用权限无关，规则层不存在身份豁免。

## 产品边界（非目标）

- **root 的身份性差异保留**：`ROOT_USER_ID = -1`、无限余额、不计费快照、`type=root` 不可通过用户接口分配 —— 这些是「root 身份」而非「管理权限」；系统管理员调用 LLM 照常扣费、照常写请求记录。
- **不放开普通用户的跨租户能力**：`normal` 用户与其它租户 admin 的隔离规则不变。
- **不改变租户隔离强度**：`tenant_id` 仍是归属标签 + 默认过滤维度，不是行级安全；系统管理员也只是「被允许选择视角」，其读写仍受所选视角约束（不能在一次请求里跨多个租户）。

## 验收标准

- [ ] main 租户 admin 与 root 都能：访问租户管理、切换任意租户视角、修改多租户开关。
- [ ] 其它租户的 admin 与 normal 用户：上述三项能力全部不可用（`403`）。
- [ ] LLM 规则约束对所有用户（含 root）一视同仁，不存在身份旁路。
- [ ] `/status.json` 下发 `is_system_admin`，前端据此显示「租户管理」菜单、顶栏视角切换、多租户开关。
- [ ] 多租户隔离关闭时，归属其它租户的 admin 仍不是系统管理员。
- [ ] root 调用 LLM 时与普通用户一样受规则约束（命中 forbid_access → 403）。
- [ ] 全局控制面在非 main 视角下：`/config.json` 写入与 `/client-config/*` 一律 `403`（与前端「设置」「客户端管理」入口的显示条件一致）；`/config.json` 读取仍对所有租户 admin 开放（侧边栏遥测 / 更新检查与模型表单计费开关会无条件读取）。

## 已知影响

- **默认单租户部署下 admin ≡ root**：多租户开关默认关闭，存量 admin 均在「一切皆 main」时创建、`tenant_id` 为 main，因此改造后全部成为系统管理员。
- main 租户 admin 成为事实上的超级管理员，可读写任何租户的数据。
