# V1.8: 多上游路由、对象存储与高精度计费 - 技术文档

## 架构概览

V1.8 的改动横跨路由、存储、计费、记录四块，均在既有 `controller → service → model` 架构上增量演进，并对模型配置结构做了较大调整。

## 多上游路由

### 配置模型

`model` 表的 `routing_config` JSON 列（自定义 cast `ModelRoutingConfig`）：

```json
{
  "upstreams": [
    { "vendor_id": 1, "vendor_model_id": 5, "enabled": true },
    { "vendor_id": 2, "enabled": true }
  ],
  "failover": { "enabled": true },
  "load_balance_strategy": "user"
}
```

旧的 model 直连 vendor 字段（vendor_id 等）移除，统一收敛到 upstreams。

### 模块结构

```text
service/routingService/
├── core.ts                                # validateConfig / resolveAvailableCandidates / selectUpstream
├── routingContext.ts                      # 记录本次已试过的上游（去重）
├── routingStrategy/
│   ├── baseRoutingStrategy.ts
│   ├── singleRoutingStrategy.ts
│   ├── loadBalanceRoutingStrategy.ts      # 按用户/按请求随机，用户种子取请求上下文 user.id
│   └── firstAvailableRoutingStrategy.ts   # 健康过滤下沉到策略类
└── types.ts
```

- **候选生成**：`resolveAvailableCandidates` 按 enabled upstream 加载 vendor / vendor_model，解析支持的协议格式
- **健康状态**：`upstreamHealthService` 用内存缓存（前缀 `upstream-health:`）记录冷却；`shouldMarkFailure` 只对 5xx / 402 / null（网络不可达）记冷却
- **failover 编排**：`senderService` 循环选择上游，非成功响应或流式异常触发下一次尝试；耗尽后抛带 routing context 的最后一次错误
- **选中的上游去重**：`routingContext.markTried` 避免同请求重复选中

## 对象存储

### 存储抽象

```text
objectStorageService
├── 位置解析：resolveStorageLocation → database | r2 | auto
├── 数据库后端：storage_record 表（object_key 主键，data BLOB）
├── R2 后端：Worker 的 R2 bucket
└── put/get/delete：主位置写入 + 备位置清理/回退
```

- record 的 `request_data` / `response_data` 改存 `record/{id}` 键；读取时按需从存储还原
- `normalizeBytes` 兼容 D1 返回的 Buffer 序列化对象 / 字节数组 / TypedArray 等多种形态
- 迁移脚本把旧记录批量复制到 storage_record；`record_payload_enabled` 关闭时不再写 payload

## 高精度计费

- **整数微元**：`user.balance` 为整数微元（迁移 `balance_units = ROUND(balance / 0.000001)`），加减均为整数运算
- **价格 JSON**：`model.prices = { input, output, cache_read }`，单位元/百万 Token；`validatePrices` 校验价格合法；`hasBilling()` 判定是否有任一价格 > 0
- **扣费时机**：请求完成按 usage 计费 → `userService.deductBalance` 扣减；请求前 `checkBalance` 预检（免费模型或无计费模块跳过）
- **换算**：元 → 微元 `toUnits(yuan) = round(yuan * BALANCE_SCALE)`

## 请求活动时间线

- `request_activity` 表：`id` 自增主键，`record_id` 唯一索引，`activities` JSON 数组（stage / level / message / details / ts）
- `requestActivityService.append` 读改写（upsert by record_id），**best-effort**：写入失败绝不导致请求失败
- 活动覆盖：请求发起、上游尝试、成功 / 中断 / 上游错误 / 流式不完整等阶段
- `record.first_token_latency`：流式记录首 token 耗时，非流式记录整体耗时
