# V1.4: 计费管理与 Responses API - 技术文档

## 架构概览

V1.4 在既有 MVC + sutando ORM 架构上新增计费模块，并扩展协议支持。技术栈为 **TypeScript + Hono + sutando（knex）**。

## 计费模块

### 数据模型

| 表 | 变更 | 说明 |
|---|---|---|
| user | + `balance` decimal | 当前余额，单位「元」（V1.8 重构为整数微元） |
| model | + `prices` JSON 文本列 | 价格配置：`{ input, output, cache_read }`，单位元/百万 Token |
| recharge_records | 新增表 | `user_id / amount / type / remark / operator`，type 为 `recharge` 或 `adjustment` |
| record | + `cost` | 单次请求消费金额 |

模型价格字段说明：早期规划稿设想 `input_price` / `output_price` 两个独立 decimal 列，实际落地统一收敛到 `prices` JSON 列（含 cache_read），价格以**百万 Token** 为计价单位。

### 核心接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/user/:id/balance/adjust.json` | 调整用户余额（充值 / 扣减），写 recharge_records |
| GET | `/balance/recharge/list.json` | 充值记录列表 |
| GET | `/balance/recharge/:id` | 充值记录详情 |

### 计费逻辑

- 请求完成后再扣费：根据 usage 的 token 数与模型价格计算 `cost`，写入 record 并扣减用户余额
- 请求前检查余额，余额不足返回 402；扣减允许余额为负（透支）的逻辑在 V1.8 细化
- 金额换算与浮点处理：后续 V1.8 引入整数微元存储以彻底消除浮点误差

**消费金额计算**（元）：

```text
input_cost  = input_tokens  / 1_000_000 * prices.input
output_cost = output_tokens / 1_000_000 * prices.output
cache_cost  = cache_read_tokens / 1_000_000 * prices.cache_read
cost = input_cost + output_cost + cache_cost
```

**充值记录**（recharge_records）：`user_id` + `amount`（元）+ `type`（recharge / adjustment）+ `remark` + `operator`；余额调整时写入。

## 前端计费界面

- 目录：`frontend/src/views/Balance/` → `Index.vue`（a-tabs 切换）+ `components/UserBalanceTable.vue`、`BalanceAdjustDialog.vue`、`RechargeRecordsTable.vue`
- API 模块：`src/api/billing.ts`（adjustUserBalance / getRechargeRecords）
- 类型：`src/types/billing.ts`（Model / User 增加价格与余额字段、RechargeRecord、请求类型）
- 模型编辑对话框与用户表格分别新增价格列 / 余额列

## Responses API 支持

- 新增 Responses 协议端点与 `ResponsesAccumulator`（流式累加）
- 协议文档按 Chat Completions / Responses / Anthropic 三类重排
- 前端集成页同步支持 Responses 端点展示

## 性能优化

- 仪表盘统计拆分为「今日明细 + 总数」两条 SQL，利用 `idx_record_created_at` 索引
- record 列表限制分页大小，避免大结果集
