# 版本文档规范

## 目录结构

```
doc/design/versions/
├── 版本文档规范.md      # 本文件，记录版本管理和命名规范
├── ROADMAP.md           # 实施路线图（版本概览 + 相关文档索引）
├── _planning/           # 规划中的设计稿（尚未落地）
├── v1.0/                # V1.0 版本文档
├── v1.1/                # V1.1 版本文档
└── ...
```

---

## 版本管理

每个版本对应一个独立子目录 `versions/vX.Y/`，版本之间以增量方式演进。**版本号取发布版本的前两位**（忽略补丁号），前后端共用同一版本号。

| 版本 | 主题 | 状态 |
|------|------|------|
| V1.0 | 基础网关能力 | 完成 |
| V1.1 | 厂商预置与部署完善 | 完成 |
| V1.2 | 前端完善与连通性测试 | 完成 |
| V1.3 | 流式记录与仪表盘 | 完成 |
| V1.4 | 计费管理与 Responses API | 完成 |
| V1.5 | Tauri 桌面与协议转换 | 完成 |
| V1.6 | Windows 跨平台支持 | 完成 |
| V1.7 | 客户端配置管理与插件 | 完成 |
| V1.8 | 多上游路由、对象存储与高精度计费 | 完成 / 进行中 |

## 文档命名规范

### 格式

```
v{版本号}_step{步骤号}_{文档类型}.md
```

### 步骤说明

每个版本按开发流程顺序编写，步骤可按需取舍：

| 步骤 | 文档类型 | 说明 |
|------|---------|------|
| step1 | product | 产品文档：目标、功能特性、产品边界、验收标准 |
| step2 | technical | 技术文档：架构概览、核心模块、接口定义、技术要点 |
| step3 | tasks | 开发任务表：任务拆分、依赖关系、验收清单（未完成版本必写） |

### 示例

```
versions/v1.8/
├── v1.8_step1_product.md
├── v1.8_step2_technical.md
└── v1.8_step3_tasks.md
```

### 专项设计文档

- **已落地功能**的专项设计（如路由、计费、客户端管理），随对应版本放入该版本目录（如 `v1.8/model_multi_upstream_routing_design.md`）。
- **规划中、尚未实施**的设计稿，放入 `_planning/` 目录并标注状态。

### 历史文档

早期规划稿已**整合进对应版本的新文档后删除**（内容保留在新文档与 git 历史中），不再单独存放 `legacy_` 文件。

---

## 新增版本流程

1. 在 `doc/design/versions/` 下创建对应子目录 `vX.Y/`
2. 按顺序编写文档：step1 → step2 → step3
3. 在 `ROADMAP.md` 的"版本概览"章节补充该版本条目，并在"相关文档"章节添加索引链接
