# V1.0: 基础网关能力 - 技术文档

## 架构概览

V1.0 确立了网关的三层基本架构，后续所有能力都在此基础上增量演进：

- **入口层**：Hono 路由 + 中间件（鉴权、上下文），对外暴露 LLM 端点与管理后台 API
- **业务层**：controller → service 的 MVC 结构，业务逻辑收敛在 service
- **数据层**：sutando（基于 knex 的 ORM）+ 数据库表（user / vendor / model / vendor_model / record）

```text
客户端 ──> Hono 路由 ──> 中间件（鉴权/上下文）
                          │
                          ▼
                     service（转发/记录/供应商匹配）
                          │
                          ▼
                    sutando ORM ──> SQLite / D1
```

## 核心模块

### 流式转发

- 服务端以 SSE 接收上游响应，向客户端中继流式 chunk
- 失败消息、流中断、类型警告等边界情况统一处理
- 流式响应累加，供请求记录使用

### ORM 与双模式

- 引入 sutando ORM，通过 dbAdapter 抽象 SQLite（better-sqlite3）与 D1 两种驱动
- `ormService` 负责连接初始化与模式切换；Worker 模式每次请求更新 D1 binding
- migrate 用独立脚本执行，Node / Worker 共用迁移 SQL

### 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| user | id / name / token / type / status / balance / created_at / updated_at | 用户与鉴权（type: normal / admin / root） |
| vendor | id / type / name / token / urls(JSON) / config / created_at / updated_at | 供应商，支持多 URL 与默认 URL 预设 |
| model | id / name / enable / prices / created_at / updated_at | 对外模型（价格字段为后续计费预留） |
| vendor_model | id / vendor_id / model_id / allowed_formats / created_at / updated_at | 供应商模型映射 |
| record | id / user_id / model_id / vendor_id / status / request_data / response_data / start_at / end_at | 请求记录 |

## 管理 API 接口一览

| 模块 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 系统 | GET | `/`、`/status.json` | 欢迎接口（验证 Token）、系统状态 |
| 用户 | GET | `/user/list.json` | 用户列表（含搜索 / 筛选 / 分页） |
| 用户 | GET | `/user/:id` | 用户详情 |
| 用户 | POST | `/user/create.json` | 创建用户 |
| 用户 | PUT | `/user/:id` | 更新用户 |
| 用户 | DELETE | `/user/:id` | 删除用户 |
| 供应商 | GET | `/vendor/list.json` | 供应商列表 |
| 供应商 | GET | `/vendor/:id` | 供应商详情 |
| 供应商 | POST | `/vendor/create.json` | 创建供应商 |
| 供应商 | PUT | `/vendor/:id` | 更新供应商 |
| 供应商 | DELETE | `/vendor/:id` | 删除供应商 |
| 模型 | GET | `/model/list.json` | 模型列表 |
| 模型 | GET | `/model/:id` | 模型详情 |
| 模型 | POST | `/model/create.json` | 创建模型 |
| 模型 | PUT | `/model/:id` | 更新模型 |
| 模型 | DELETE | `/model/:id` | 删除模型 |

> 注：管理接口需管理员 Token 鉴权；列表统一走分页封装（`createListResponse`），错误返回 `{ error, message }`。

## 前端技术

- **技术栈**：Vue 3 + TypeScript + Vite + Ant Design Vue + Vue Router + Pinia + Axios；辅助 Day.js / lodash-es / VueUse
- **目录结构**：`src/api`（system / user / vendor / model）、`src/components/layout|common`（AppLayout / TokenDisplay / StatusCard 等）、`src/composables`（useAuth / useTable）、`src/router`、`src/stores`（auth / app）、`src/types`、`src/views`（Login / Dashboard / User / Vendor / Model）
- **认证**：Token 存 localStorage，Axios 请求拦截器注入 Authorization，响应拦截器统一错误处理（401 跳登录）
- **环境变量**：`VITE_API_BASE_URL`、`VITE_APP_TITLE`

### 用户角色

- **管理员（Admin）**：完整系统权限，管理所有资源与配置，可查看全部请求记录
- **普通用户（Normal）**：仅能访问 LLM API 端点（`/v1/chat/completions`、`/v1/messages`），无法访问管理后台

### 设计规范（基线）

- **色彩方案**：主色 `#3B82F6`、成功 `#10B981`、警告 `#F59E0B`、错误 `#EF4444`、背景浅灰、卡片白色、文字深灰 / 中灰（后续 v1.4 统一暗色主题时演进）
- **交互反馈**：加载态（loading / 骨架屏）、成功绿条提示（3s 自动消失）、错误红条提示、删除二次确认、表单即时校验
- **响应式**：桌面（>1024 全布局）、平板（768–1024 侧边栏可折叠）、移动（<768 侧边栏隐藏 + 菜单按钮）

### 非功能性需求

- **性能**：首屏加载 < 2s、列表加载 < 500ms、分页加载避免一次性拉取过多
- **兼容性**：现代浏览器（Chrome / Firefox / Safari / Edge），不支持 IE
- **安全性**：Token 默认隐藏、敏感信息加密 / HttpOnly Cookie、HTTPS
- **可访问性**：键盘导航、表单 label、颜色对比度符合 WCAG

## 技术要点

- API 采用 REST 风格，URL 以 `.json` 结尾；不依赖 ORM 的 findOrFail（避免返回 404 而非 JSON）
- 统一默认导出，调用方式 `模块名.方法名`
- 前端为 Vue 3 + Ant Design Vue，与后端前后端整合部署
