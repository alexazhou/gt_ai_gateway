# 设计文档规范

## 目录结构

```
doc/design/
├── 设计文档规范.md       # 本文件，记录设计与文档命名规范
├── ROADMAP.md            # 实施路线图（发布版本概览 + 相关文档索引）
├── 2026-03-13-basic-gateway/                    # 里程碑：基础网关能力
├── 2026-06-28-client-config-plugin/             # 里程碑：客户端配置管理与插件
└── ...
```

设计文档**按里程碑/功能主题组织，目录名为 `{date}-{feature}`**，不再按版本号划分目录。日期取该功能落地的版本发布（tag）日期，如 `2026-07-04` 对应 v1.8 的首个 tag。

## 文档命名规范

### 目录命名

每个里程碑/功能一个子目录，采用 `{date}-{feature}` 格式，feature 用 kebab-case 英文主题（如 `multi-upstream-object-storage-billing`）。

### 步骤文档

每个里程碑内按开发流程顺序编写，文件名**不带版本号前缀**，步骤可按需取舍：

| 文件 | 文档类型 | 说明 |
|------|---------|------|
| `step1_product.md` | product | 产品文档：目标、功能特性、产品边界、验收标准 |
| `step2_technical.md` | technical | 技术文档：架构概览、核心模块、接口定义、技术要点 |
| `step3_tasks.md` | tasks | 开发任务表：任务拆分、依赖关系、验收清单（未完成功能必写） |

### 示例

```
2026-07-04-multi-upstream-object-storage-billing/
├── step1_product.md
├── step2_technical.md
├── step3_tasks.md
├── model_multi_upstream_routing_design.md
├── request_record_and_activity_design.md
└── upstream_failover_last_error_design.md
```

### 专项设计文档

- **已落地功能**的专项设计（如路由、计费、客户端管理），随所属里程碑放入对应目录（如 `model_multi_upstream_routing_design.md`），命名采用 `{feature}_design.md`。
- **规划中、尚未实施**的设计稿，可暂存在仓库根或其他暂存位置，待落地时归入对应 `{date}-{feature}/` 目录。

### 历史文档

早期规划稿已**整合进对应里程碑的新文档后删除**（内容保留在新文档与 git 历史中），不再单独存放 `legacy_` 文件。

## 新增功能流程

1. 在 `doc/design/` 下创建子目录 `{date}-{feature}/`（日期用功能落地的版本发布日期，进行中可先用当前日期并在 ROADMAP 标注状态）
2. 按顺序编写文档：step1 → step2 → step3
3. 在 `ROADMAP.md` 的"版本概览"章节补充对应条目，并在"相关文档"章节添加索引链接
